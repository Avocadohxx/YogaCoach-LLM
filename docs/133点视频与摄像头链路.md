# 133 点视频与摄像头链路

主入口为 Source133 → capture 服务 → `/api/pose/frame` → 本地 RTMW → 133 点特征 → 在线规则 → LangGraph → SQLite。

浏览器视频仅提交新解码帧，最长边不超过 960。摄像头通过新呈现帧确认画面推进，使用单调采集时间统计持续性；文件视频按原媒体时间统计动作持续性，墙钟仅用于请求耗时与练习页面总用时。拖动、播放速率改变、暂停、缓冲与来源切换会撤回旧证据，重新建立 stream_id。后端允许新流时间倒退，但帧序号仍递增。

来源切换会暂停旧视频，停止轨道，清除 srcObject/src 并释放文件 URL。暂时失败最多尝试四次，有退避；手动“重新连接”可重试。旧 generation 和已取消请求不得更新新来源。

输入为原图像素 keypoints[133][2] 与原始 scores[133]；不转为 MediaPipe 33 点。直接关键点分析接口保留兼容，但不能自行产生正式纠错权限。只有后端图像推理、匹配的有效会话和审核规则可进入正式链路。

当前使用单人全图 ROI，没有多人检测器。上传的不是完整原视频文件，不支持后台长视频任务。所有导出性能信息均为时序统计，不包含图像与关键点。

新帧优先使用 requestVideoFrameCallback，兼容回退使用呈现帧计数；无法确认新帧的浏览器拒绝分析。快速播放可能降低可观测采样覆盖，不能承诺不同速度下捕获完全相同的事件；采样不足时中断连续性，不补造证据。

验收需覆盖：两种来源切换、缓冲和冻结、视频跳转、播放速度、网络错误、结束与卸载。自动化包括时钟、采集服务、真实 React 来源组件与页面生命周期；实际浏览器设备仍需人工验证。
