# A → B 关键点格式

每个有效帧包含 `pose_id`、`timestamp_ms`、`camera_view: front`、`landmarks`（严格 33 点）。与 contracts/mock/landmarks_tadasana.json 对齐。时间戳由源视频帧号及 FPS 计算，单位毫秒。

坐标来自 MediaPipe image landmarks：x 向右、y 向下，相对图像宽高归一化；z 以髋部中点为原点，越小越靠近摄像头，尺度约同 x，不是米。左右指人体自身左右。提取时不镜像、不重新居中、不做世界坐标转换。浏览器端应传入相同的未镜像图像坐标。

索引顺序：0 鼻；1–3 左眼内/中/外；4–6 右眼内/中/外；7/8 左/右耳；9/10 左/右嘴角；11/12 肩；13/14 肘；15/16 腕；17/18 小指；19/20 食指；21/22 拇指；23/24 髋；25/26 膝；27/28 踝；29/30 脚跟；31/32 脚尖。成对索引均为左/右。

visibility 是可见性估计。默认要求肩、肘、腕、髋、膝、踝全部 >= 0.6 且在画面内；全部点必须有限值。不填零、不插值，检测失败或不满足条件的帧跳过，保留原时间间隔。脚尖、脚跟未纳入必需点，B 若使用这些点需另行判断可见性。

参考 JSON 顶层保留同样四字段，附加 metadata 记录来源和质量统计；参考取最接近坐标中位数的实际帧。它是候选参考，必须人工确认动作、正面视角、稳定保持区间及侧弯方向。可见性通过不代表动作正确。侧弯左右及不同保持区间应分别提取到不同输出目录，避免混合过渡阶段。
